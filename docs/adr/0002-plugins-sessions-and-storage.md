# 0002：采用三端插件、复用 STAR 会话并简化运行设计

状态：已接受，实施进度见 [TODO](../../TODO.md)。

日期：2026-11-03

关联：[规格](../specs/spec-2026-11-03-14-23.md) · [实施计划](../plans/plan-2026-11-03-14-23.md)

## 背景

程序、MCP 配置和 Skill 分别安装，固定环境不会随源码更新，增加了维护步骤。实际使用产生的 `starbridge-inspection` 目录包含多份算例副本，项目目录承担了不必要的磁盘占用。

现有实现还包含逐请求源文件摘要、签名引用、重复目录编译、宽范围快照比较和多套兼容结果。部分只读失败会冻结会话。这些机制增加了大算例的运行成本，也不适合用户与 Agent 共用已有 GUI 会话的方式。

## 决定

1. 仅适配 Codex、Claude Code 和 DSH 插件。三端共用程序与 Skill，按同一版本交付，使用宿主原生更新机制，不另建升级器；其他 Harness 通过源码或通用接口自行接入。聚合市场由 `my-awesome-vibekits` 的统一 catalog 生成三端目录，StarBridge 独立维护插件包；DSH 采用原生 bundle 与 JSON 索引。
2. 优先连接匹配的已有 STAR GUI／服务器，没有可用会话时启动后台服务并直接加载原算例。取消强制副本和日常源文件摘要检查，区分外部会话的断开与自有会话的停止。
3. 算例遵循保存／另存为语义；项目报告和导出默认放在项目 `.starbridge`，运行数据放在用户 `~/.starbridge`。插件安装目录只承载程序和 Skill，三端共用项目产物。
4. 删除签名引用和重复计划文件往返，收敛接口、缓存和结果。只读失败不冻结整个会话；普通写入保留目标、旧值、必要约束和回读，不再强制比较旧 Inspector 全范围快照。
5. 先减少重复工作和迁移已有能力，不预设新的常驻 RPC 系统，不用新增验收或校验机制代替简化。

## 取舍与既有设计的关系

不再通过日常操作证明原始磁盘文件始终不变，也不把完整快照不变作为普通赋值成功的条件。保留实际操作所需的会话与对象身份、类型和单位约束、旧值冲突检查及写后回读；结果未知的写入不自动重试。

继续采用 [ADR 0001](0001-runtime-discovery.md) 的运行时发现方向。其中“当前文件／会话 CLI、MCP 和人工目录继续兼容。”以及保留原会话 Runner 的安排，由本决定调整：现有有效适配先迁移再移除旧入口，会话采用优先连接已有 STAR 的方式。版本支持范围不因简化而自动扩大。

本决定也替代了[原分发计划](../archive/plan-2026-11-01-14-42.md)中“安装 Skill 与接入 MCP 是两个步骤。”的安排，改为三端插件统一交付。旧文档保留已有实现和工作记录，后续改造按关联规格和计划推进。
