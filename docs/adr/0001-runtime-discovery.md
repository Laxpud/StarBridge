# 0001：采用运行时对象树与属性发现

状态：已接受，尚未完成产品化实施。

日期：2026-10-30

## 决定

StarBridge 以当前算例的对象层级作为 Agent 的主要导航，通过运行时子对象枚举、Bean 属性描述符和通用类型适配，按需发现、描述和读取设置。保留 STAR 的对象名称、上下文和关系，不要求完全复刻 GUI 的分组、排序、隐藏或属性折叠。

执行计划由运行时元数据、精确版本的 API 声明和已接受的适配规则生成；不再以逐属性人工维护的完整支持清单作为未来新增能力的必要条件，也不要求用户在查询前生成完整配置目录。版本材料、通用规则、特殊约束和禁止规则继续维护，发现结果与可执行能力分别表达。

## 原因与取舍

已有人工目录能够提供明确的调用契约，但每增加一个设置都补充访问路径和属性映射，会限制覆盖扩展。真实算例的[只读探查依据](../archive/spec-2026-10-30-12-24.md#验证依据)表明，属性元数据可以生成通过现有 Core 校验的读取计划，并复用原 Java 执行器。对象树还需结合属性关联和 input 解包，单独遍历 `getChildren()` 不能发现全部设置。

人工维护转向对象机制、值类型、特殊操作及例外。未知返回类型、尚未确认只读性的访问方法和未适配代理节点保留为有原因的发现结果；不会为了补齐展示而逐个模拟 GUI 节点，也不会仅凭 getter/setter 名称开放调用。代价是部分节点暂时只能描述，发现范围和缓存有效性必须显式返回。

## 实施边界

- 首阶段只产品化对象导航、属性发现和只读访问；实验中的 setter 元数据不构成写入支持。后续写入按已接受规则、当前条件和具体新值分别检查。
- 保留现有会话 Runner、临时 Java 客户端、Core 校验、旧状态检查、回读、Diff、文件重载核对及不确定状态处理；本决定不要求立即改成常驻 Java 适配器。
- Agent 通过树导航或搜索找到真实对象和属性引用。文档补充语义，Skill 组织任务，少量术语别名辅助搜索；训练知识和缓存不能代替当前会话事实。
- 当前文件／会话 CLI、MCP 和人工目录继续兼容。保存本决定及计划不代表启动实施，不开放自动写入。

本决定替代 [StarBridge 设计](../../StarBridge.md#版本化对象属性与操作目录)中“目录外属性必须逐项补充人工映射才能获得执行能力”的目标设计；旧目录仍是当前产品行为及迁移基线。
