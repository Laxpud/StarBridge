# 三端插件、会话接入与运行简化规格

状态：方案已确认，实施进度见关联计划。

关联：[ADR 0002](../adr/0002-plugins-sessions-and-storage.md) · [实施计划](../plans/plan-2026-11-03-14-23.md)

## 分发

只为 Codex、Claude Code 和 DeepSeek Harness（DSH）适配插件。三端共用一套 Core、MCP、Java 资源和 Skill 内容，只分别适配插件声明、启动和 Skill 加载。

插件是正式安装与更新入口，程序和 Skill 绑定同一发布版本。用户无需分别安装 Python 包、配置 MCP 和安装 Skill。必要的 Python 运行环境由插件配套的初始化机制准备并复用，放在用户目录；更新后使用与插件对应的程序版本。

使用三端原生插件更新机制，不另建统一升级器。Python 包可以继续作为底层交付形式，不要求用户单独操作。保留源码安装及通用 CLI／MCP 说明，其他 Harness 自行接入，不维护其专用适配和安装支持。

## 会话接入

优先连接已经打开且与目标算例匹配的 STAR GUI 或服务器；没有可用会话时，由 StarBridge 启动后台会话，直接加载原算例。

不再强制创建 `working.sim`，也不自动生成备份副本。普通读取和修改以 STAR 中当前加载的算例为对象，不再反复计算源文件 SHA256，也不以另一套源文件属性检查替代它。

会话区分外部已有和 StarBridge 启动两种来源。结束外部会话的连接时只断开，不关闭用户的 STAR；StarBridge 启动的会话才涉及停止其拥有的进程。保留会话、对象和进程身份的必要判断。

内部会话目录由服务管理，对外使用会话标识，Agent 不再负责命名或选择日志目录。

## 保存算例与项目产物

- **保存**：按用户保存指令写回当前加载算例的路径。
- **另存为**：写入用户指定的新路径；未指定目录时建议放在当前算例旁边。
- 没有保存路径的 GUI 算例，需要确定文件名和位置。
- 连接、读取和修改参数均不自动保存算例。

算例文件保留在正常的工程目录中，不默认放入 `.starbridge`。保存和导出完成后返回实际绝对路径。

项目位置在连接会话时确定一次：优先采用明确的项目目录，没有时采用算例所在目录，后续调用沿用。无需复杂的向上搜索或项目识别。

| 内容 | 默认位置 |
|---|---|
| 保存或另存的 `.sim` | 当前算例路径或用户指定路径 |
| 检查报告、修改摘要 | `<项目>/.starbridge/reports/` |
| 参数等导出结果 | `<项目>/.starbridge/exports/` |
| 会话状态、运行日志、临时文件 | `~/.starbridge/sessions/` |
| 可重建的元数据和编译缓存 | `~/.starbridge/cache/` |
| 程序、平台适配入口和 Skill | 各平台插件安装目录 |

项目 `.starbridge` 只在实际生成产物时创建。用户指定位置或项目已有的 `reports/`、`analysis/` 等组织方式优先于默认位置。项目产物由三端共用，不保存在各平台插件目录中。

运行数据集中到用户目录。稳定的安装相关缓存跨会话、跨项目复用；临时日志和缓存采用简单的大小或时间保留规则，不另建清理服务。清理只处理已结束且不再需要恢复的数据，保留运行中或结果未确认请求所需的状态。

## 失败处理与写入范围

区分请求失败、请求仍在执行和写入结果未确认。只读请求失败不自动冻结整个会话；仍在执行时保持忙碌，确认结束后可以继续操作。写入结果未确认时允许查询状态和读取核对，不自动重复写入。

普通赋值只检查目标对象、必要前提、预期旧值、写后目标值及操作确实涉及的少量关联项。不再强制要求旧 Inspector 覆盖的其他设置全部不变。完整快照和 Diff 作为用户主动要求的审查功能，不作为每次赋值的前置步骤。

保留类型、单位、必要约束和写后回读。现有版本适配范围继续有效，合并重复检查不意味着开放尚未适配的版本或任意 getter／setter。

## 读取、执行与接口简化

- 对象引用和分页游标取消 HMAC 签名、专用密钥及其管理逻辑；采用会话内短 ID，由服务查找对象，保留会话归属和对象是否有效的判断。
- 内部计划直接传递，取消为内部调用写入目录 JSON 后再读回的步骤，合并重复加载和检查。
- 稳定的类型适配结果按安装版本复用。Javadoc 保留为适配依据，不在每次读取时重新计算相关文档的内容摘要。
- 读取不准备无关的写入计划，属性分页不重复准备全部描述和写入支持信息。
- 减少每次请求重复生成宏和启动临时客户端的开销，先处理可复用的执行资源和可合并的请求；本方案不预先引入常驻 RPC 系统。
- 对外收敛对象、属性、读取和修改的表达方式，复用现有目录中的有效适配。迁移已有能力后再移除旧入口，不长期维护多套原型格式及相互投影。
- 正常运行只保留必要会话状态、简短操作记录和错误诊断。详细宏、执行计划及完整快照按调试需要保留，MCP 不重复返回整理后的属性和包含相同数据的底层结果。

本规格只记录上述已确认的调整，不新增验收、测试矩阵或其他校验机制。
