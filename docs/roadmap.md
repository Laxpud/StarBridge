## 后续里程碑

只读运行时发现已交付，当前按规则族推进受控写入迁移；复杂结构操作和 Skills 按实际需求确定范围。版本核验贯穿各阶段。前两个阶段已获授权，具体任务状态仅在对应 Plan 维护。

### 运行时对象树与属性发现

目标：Agent 沿 STAR 实际对象层级按需导航、描述、读取和搜索设置；不需要预先生成完整配置列表或知道精确 Java 标识符，不要求完全复刻 GUI。

方案：[ADR](adr/0001-runtime-discovery.md) · [Plan](plans/plan-2026-10-30-12-24.md) · [Spec](specs/spec-2026-10-30-12-24.md)。首阶段实施范围为 Plan 的 P1—P3，完成条件为 Spec 的 R1—R10。

初期只开放按已接受规则生成的读取，保留未知代理节点、复杂类型和未检查条件的明确状态。真实算例探查只证明已记录的只读路径，证据范围见 Spec。

更广的设置访问由按需发现与读取承担。[Inspector](inspector.md)保留稳定摘要及旧字段契约，兼容核验归入 P3；现有对象清单不等于完整设置导出。修改影响范围的验证调整归入后续 P4。

### 通用规则驱动的受控写入迁移

目标：对具备完整类型规则、操作条件和验证依据的属性生成写入计划，逐批替代重复人工映射；人工维护特殊操作、前置条件和版本例外。实施范围见 [Plan P4](plans/plan-2026-10-30-12-24.md#p4后续受控写入迁移)，验收要求见 [Spec W1—W4](specs/spec-2026-10-30-12-24.md#版本迁移与后续写入)。本阶段已获授权，在只读里程碑完成后继续推进。

写入继续保留旧状态检查、实际调用前的必要重查、单次尝试、回读、Diff、显式保存和文件重载核对。按目标及受影响对象验证的新机制具有等价或更强依据前，不取消现有快照要求；setter 元数据、`writable` 标志或只读成功不能证明当前可写。

### Skills

Skills 按所需能力分批推进：只读审查类可在所需发现与读取能力验收后开展，无需等待全部写入；配置类依赖相应写入规则和操作语义完成验收。候选包括 `case-audit`、`mesh-setup`、`overset-mesh`、`rotor-case`、`oge-case`、`nwse-case`、`vof-setup` 和 `solver-setup`，具体交付范围另行确定。

Skills 通过对象树导航或属性搜索取得当前版本的实际对象和设置，组织检查顺序与业务工作流，并使用已提供的用户、项目及算例背景；持久化工作记忆另列 Backlog。对象 API 绑定和版本差异由 Bridge 的发现、规则与执行器维护，避免每个 Skill 重复维护 Java 调用或完整配置列表。

Tool 决定 Agent 能做什么，Skill 描述 Agent 如何完成工作。

## 覆盖范围与版本验证

以下是选择规则与验收样例的依据，不另立一个覆盖全部配置的大里程碑。已有领域能力及验证边界统一见[目录修改](catalog-modifier.md)和[版本说明](catalog-versions.md)；原 Modifier 与目录阶段的剩余缺口按读取、写入和结构操作分别承接：

| 覆盖范围 | 尚需扩展或验证的内容 | 任务归属 |
|---|---|---|
| Mesh Controls | 其他网格控制的值类型、单位、范围及关联 | 通用发现／读取与相应写入规则 |
| Boundary Parameters | 常量标量／向量之外的 Profile 方法、当前方法条件及切换关系 | 发现／读取、写入规则；方法切换按专门操作验收 |
| Selected Physics Settings | 其他物性与求解设置、真实张量布局与方向、材料及多系数方法、模型依赖 | 发现／读取、写入规则；模型启停及方法切换另列结构操作 |
| Simulation Operations | 块关系读取、块修改及结构循环检查 | 发现／读取与复杂结构操作 |
| 其他算例内设置 | 几何、表格、报告、监视器、场景等缺失值类型、查询谓词和操作语义 | 按实际缺口选取通用规则或专门操作，不逐对象建立 Tool |

用代表性算例验证发现机制、类型规则和特殊约束，保留宏录制、精确版本 API 材料及实测结果的对应依据；根据缺口决定新增通用规则或例外。当前算例未实例化的类型可保留在版本材料中，但不计为当前对象或已实测能力。

2510 的旧目录及代表性读写已有支持；新的运行时发现机制尚未在 2510 核验，首阶段只接入已核验的 2602 精确 Build。两者的支持范围分别记录，不能继承旧目录的证据或仅凭版本接近判定兼容，具体安排见 Plan P1。

各阶段按规则族、实例状态和精确版本限定验收范围；分别统计已发现、可读取、具备写入实现和已实测能力，说明范围、统计基准及未适配、条件不满足或证据不足的原因。条件拒绝、单位与关联身份、需保持状态及持久化检查按 Plan／Spec 执行，不再维护一份重复的全分支待办。静态发现、编译或一次成功回读不代表全部分支通过，也不代替 CFD 物理合理性判断。

## Backlog

### 网格与求解执行接口

网格生成与求解仍需独立执行入口，不能合并进配置修改工具。后续明确运行状态、停止与取消、失败恢复及实际结果核验，再通过共享 Core 接入 MCP；当前没有对外执行工具。

### 复杂结构操作

按实际任务分别确定创建／删除、模型启停、方法切换、操作块修改和复杂查询的范围。为每类操作明确依赖、结构关系、循环检查、切换前后状态及失败后的处理方式，并按 P4 的写入要求验收；不能将其包装为任意属性赋值，或由只读发现成功推定支持。

### 常驻 Java 适配器

目标：减少临时 Java 客户端的启动开销，并评估常驻缓存及事件监听。待明确请求接收、API 调用线程、资源释放、异常恢复与缓存失效。当前继续使用短生命周期客户端；本项不作为只读发现的前置条件，也不与 GUI 接入绑定交付。

### GUI 会话接入

目标：允许用户和 Agent 操作同一个 GUI 会话。待明确会话身份与连接方式、用户操作和 Agent 操作的协调、状态变化检测及冲突处理。操作条件描述、Bridge 会话锁和回读不能替代跨客户端并发协调；实施范围与常驻适配器分别确定。

### 持久化工作记忆

目标：跨对话保留用户偏好、项目约定和算例背景。待明确用户、项目、算例身份关联，以及记忆检索、纠正与失效规则；不作为发现、读写规则或首批 Skills 的前置条件。
