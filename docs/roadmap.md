## 后续里程碑

按“版本目录与通用读写基础 → 目录覆盖扩展与版本演进 → MCP → Skills”的顺序推进。各阶段同步直接受影响的文档；GUI 会话接入和持久化工作记忆仍保留为目标，实施时点另行确定。

### 目录覆盖扩展与版本演进

目标：通过目录条目、通用类型适配器和必要的特殊操作适配，逐步覆盖算例配置；版本变化主要通过目录差异和映射更新处理。

原 Modifier 未完成项纳入此阶段，保留其读取、检查和回读要求：

- Mesh Controls：完善网格控制的属性、单位、引用和修改约束。
- Boundary Parameters：明确区域、边界、Profile 方法与属性的定位及切换关系。
- Selected Physics Settings：完善模型启停、依赖、物性和求解设置的读写。
- Simulation Operations：完善工作流、操作类型、结构关系和修改后的保存验证。

覆盖继续延伸到几何、其他物理与求解配置、表格、报告、监视器、场景及其他算例内设置。按缺失的属性类型和操作语义补齐适配，避免为每个对象维护独立工具。

同时完成以下版本与覆盖工作：

- 用代表性算例补充目录，保留宏录制、API 材料和实际验证的对应依据；当前算例中未实例化的类型仍可保留在版本目录中。
- 分别统计已发现、可读取、具备写入实现及已实测条目，列出未适配、条件不满足和证据不足的原因；覆盖率说明所用版本、范围及统计基准。
- 建立另一明确 STAR 版本的目录，比较 API 及元数据变化，复用通用适配器并处理映射或语义差异；不能仅凭版本接近就假定兼容。
- 验证属性依赖、方法切换和结构修改；未知或未适配操作应有明确结果，成功回读不代替 CFD 物理合理性判断。

### MCP

将目录驱动的 Core API 暴露为少量稳定的 Tools 和 Resources，包括对象查找、属性与操作描述、读取、统一修改以及目录能力查询。

CLI 与 MCP 共用 Inspector、Modifier、类型适配器和版本目录。具体对象的新增属性或版本映射变化原则上更新目录；出现新的值类型或操作语义时再扩展执行器。网格生成与求解使用执行入口，会话启停与保存使用生命周期入口。

会话管理和工作记忆访问也通过共享 Core API 接入，具体契约依各自实现进度确定。接口草案见[设计文档](../StarBridge.md#mcp)。

### Skills

逐步积累 STAR-CCM+ 工作流 Skills，例如 `mesh-setup`、`overset-mesh`、`rotor-case`、`oge-case`、`nwse-case`、`vof-setup`、`solver-setup` 和 `case-audit`。

Skills 查询当前版本的目录能力和算例状态，通过统一接口组织工作流，并结合用户、项目及算例记忆理解背景。对象 API 映射和版本差异由目录与执行器维护，避免每个 Skill 重复维护 Java 调用。

Tool 决定 Agent 能做什么，Skill 描述 Agent 如何完成工作。

## Backlog

### Inspector 读取深度与补充验证

当前字段契约与未实测分支见 [Inspector 对象快照](inspector.md)。非空 Simulation Operations、向量参数、读取失败及其他设置的覆盖纳入[目录覆盖扩展与版本演进](#目录覆盖扩展与版本演进)；现有对象清单不等于完整设置导出。

### 常驻 Java 适配器与 GUI 接入

价值：在后台服务常驻的基础上，进一步消除每次启动 Java 客户端的开销；允许用户和 Agent 操作同一个 GUI 会话。
待明确：常驻请求接收、API 调用线程、异常恢复，以及共享状态协调。目录可以描述操作条件，但不能替代实际并发协调。当前只实施短生命周期客户端方案，此项后续再研究。

### 持久化工作记忆

价值：跨对话保留用户偏好、项目约定和算例背景。
待明确：用户、项目、算例身份关联，记忆检索、纠正与失效规则；不作为当前目录与读写基础的前置条件。
