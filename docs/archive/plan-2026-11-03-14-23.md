## 实施顺序

| 顺序 | 实施安排 | 详细安排 |
|---|---|---|
| 1 | 先调整会话连接、进程归属、保存语义及运行数据位置，为连续读写提供统一会话。 | [会话与存储](#会话与存储) |
| 2 | 在会话状态中区分请求失败、忙碌和写入结果未确认；收窄普通赋值检查，替换签名引用。 | [状态与写入](#状态与写入) |
| 3 | 复用类型适配与执行资源，减少计划文件往返和重复准备；迁移已有能力后移除旧接口与结果投影。 | [接口与执行](#接口与执行) |

第 4 部分的市场接入不依赖第 3 部分的接口迁移完成。减少客户端启动开销先从资源复用和请求合并入手，不预设常驻 RPC 架构。行为与存储约定以关联规格为准。

## 实施要点

### 会话与存储

- 优先连接匹配的已有 STAR GUI／服务器，没有可用会话时启动后台服务并直接加载原算例。
- 区分外部会话和自有会话，分别处理断开连接与停止进程。
- 移除强制算例副本和源文件 SHA256 检查，不自动生成备份副本。
- 实现保存当前算例与另存为的语义，保持保存由明确指令触发。
- 按规格管理项目位置、项目 `.starbridge` 产物和用户 `~/.starbridge` 运行数据，隐藏内部会话路径的管理细节。
- 精简常规运行产物，按调试需要保留详细文件，并采用简单的日志与缓存保留规则。

### 状态与写入

- 区分请求失败、仍在执行和写入结果未确认，取消只读失败导致的会话冻结，允许通过状态查询和读取核对未确认写入。
- 将普通赋值的检查限制在目标、旧值、回读及必要关联项，取消强制的旧 Inspector 全范围不变检查。
- 将完整快照和 Diff 保留为按需审查功能。
- 使用会话内短 ID 替换对象和分页引用的 HMAC 签名，删除专用密钥及管理逻辑。

### 接口与执行

- 改为直接传递内部计划，去除写入 JSON 后再加载及重复检查。
- 复用安装版本相关的类型适配和缓存，取消每次读取的 Javadoc 内容摘要检查。
- 去除读取和分页中的无关写入计划及重复描述准备。
- 从复用执行资源、合并请求入手，减少重复宏生成与客户端启动，不预设常驻 RPC 架构。
- 统一对外对象、属性和读写表达；迁移现有能力后移除旧接口及结果投影。
- 精简 MCP 返回内容，去除同一数据的重复包装。

覆盖统计与普通赋值共用实际回读集合规则，并识别统一结果中的目录、版本、对象和操作标识；历史全属性证据继续按原格式核对。具体接受条件见[覆盖报告](../tech/catalog.md#分项覆盖报告)。

### 插件交付

- 为 Codex、Claude Code 和 DSH 提供轻量插件适配，共用程序与 Skill 内容。
- 通过插件初始化必要运行环境，使程序和 Skill 使用同一发布版本。
- 使用三端原生安装与更新入口，取消用户分别安装程序、MCP 配置和 Skill 的流程，不另建升级器。
- 保留源码与通用 CLI／MCP 接入说明，停止维护其他 Harness 的专用适配。

## 市场接入与安装验证

2026-11-03 的安装交付范围为第 4 部分，不包含第 3 部分的接口迁移。StarBridge 维护三端插件包，`my-awesome-vibekits` 维护统一 catalog 和三端生成索引。用户已授权两个仓库提交、推送和发布后 DSH 安装验证；该授权属于此次安装交付，不延伸为后续修改的提交授权。

安装验证使用隔离的客户端配置，只检查原生安装、MCP 握手／工具发现及 Skill 枚举／加载。只使用控制协议或官方 provider，不发送模型消息，不打开 STAR，不更新日常安装，不发布 npm／PyPI 包。

DSH 索引只收录具有真实发布来源的版本；未提交源码通过本地 bundle 验证，不伪造发布 commit 或时间。远端安装采用 GitHub Raw 索引和固定 commit 的 Git 来源。

复用两个仓库适用的现有检查，不新增自动测试文件，不增加模型工作流或真实算例验收。静态索引验证、本地安装验证和已发布市场安装分别记录。任务状态见 [TODO](milestone-2026-11-04-12-33-plugins-sessions-and-interface.md#当前里程碑三端插件会话接入与运行简化)，实际结果与限制见[安装证据](../evidence/distribution.md#本地安装验证2026-11-03)。
