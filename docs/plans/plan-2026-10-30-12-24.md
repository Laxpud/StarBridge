# 运行时对象树与属性发现实施计划

状态：P1—P3 已完成；P4 已授权并进入写入验收，按阶段提交和推送。旧入口兼容不作为完成门槛，执行安全与验收边界保持。

依据：[ADR 0001](../adr/0001-runtime-discovery.md) · [行为规格](../specs/spec-2026-10-30-12-24.md) · [路线图](../roadmap.md#运行时对象树与属性发现)

## 目标与首阶段完成条件

Agent 可以从实际算例根节点逐层导航，在不知道 Java 类或精确属性关键词的情况下发现设置，读取属性说明及支持的值；也可以按名称、说明和少量术语别名搜索，再用返回的对象引用访问目标。新增的同类属性由通用规则生成读取计划，人工主要维护机制、类型及例外。

首个实施里程碑覆盖下列 P1—P3，完成条件以 Spec 的 R1—R10 为准：导航、描述、读取、搜索、身份与缓存失效、局部错误及现有入口兼容均有明确结果；新增路径不包含可执行写入。P4 在只读阶段验收后继续实施，已由本次用户指令授权。网格／求解执行、GUI 接管、完整 GUI 复刻、常驻 Java 服务和持久化工作记忆不在本计划首阶段内。

## P0：实施依据

- [x] 完成真实算例的描述符和对象遍历探查，并通过原执行器及现有 CLI 验证自动生成的只读映射。
  - 证据范围与限制统一见 [Spec 验证依据](../specs/spec-2026-10-30-12-24.md#验证依据)；此项不表示产品发现接口已经实现。

实施启动时核对当前代码和 STAR 安装是否仍符合该基线。已有证据未覆盖的代理节点、动态范围注解及版本分支按下列任务处理，不把它们视为已验收能力。

## P1：发现契约、规则与版本依据

- [x] 落实 Spec 的节点、属性、关联、完整性、能力状态和分页契约，为新接口使用独立 schema，保留旧接口参数与输出。
- [x] 建立发现提供器和类型规则的注册机制，明确每条规则的适用版本、类型、只读调用依据、input 解包方式和不支持原因；禁止规则优先。
- [x] 将本轮探针中可复用的描述符解析、去重和计划生成整理为产品模块；实验输出与生产目录分开，不把整个实验目录直接移入运行依赖。
- [x] 为 2602 精确 Build 接入新能力。2510 保持已有入口，新增发现能力在独立核验前明确返回版本未支持。
- [x] 明确默认算例范围及库资源范围。以类型和关系规则区分材料数据库等资源，不把实验中的英文分支名称过滤直接作为生产依据。

交付：可校验的发现数据和规则契约；未知或禁止调用只返回元数据及原因。此阶段不自动调用所有带 `get` 前缀或 Bean 注解的方法。

## P2：按需导航、描述与只读执行

- [x] 从算例根节点枚举 CSO 子对象，返回分页节点与结构化路径；节点展开与属性读取分开，未展开不表示为空。
- [x] 核验非 CSO 代理或分组是否具有可复用的枚举／描述机制。实现已有依据的通用提供器；其余返回不支持说明，不逐个复刻 GUI 行为。
- [x] 解析实际 Bean 描述符，按声明类、getter 签名和上下文去重；分别保留显示名称、程序标识、隐藏标记和来源。
- [x] 接入基础值、标量／向量 input、枚举 input 规则；通过已确认的解包方法连接数量或选项对象，保留单位、坐标约定及关联身份。
- [x] 将发现信息编译成明确的只读计划，复用 Core 的版本／签名校验和 `CatalogRuntime`；计划缺少依据时停止在描述状态。
- [x] 实现会话内句柄校验、可重建路径的跨加载重新解析和类元数据缓存；处理对象消失、重建、方法变化及缓存过期。
- [x] 接入局部读取错误、节点数／深度／耗时限制、分页和重复关系去重；完整性仅针对请求范围。
- [x] 用真实工作副本验收 R1—R6、R8—R10，记录有效范围、错误和未覆盖分支。对动态范围方法使用确有该声明的实例核验，不用静态注解或普通 `getRange()` 成功代替。

交付：Agent 能按实际层级找到设置，并通过自动计划读取；产物中所有新增写入入口仍关闭。

## P3：搜索与统一入口

- [x] 将逻辑操作接入共享 Core、JSON CLI 和本机 MCP，新增方法按 Spec 暂定名称实现并在交付时同步契约；不为每个对象生成独立 Tool。
- [x] 建立对象名称、路径、属性显示名称、说明和程序标识的索引；提供小规模中英文术语别名，搜索结果携带匹配依据及对象上下文。
- [x] 区分只搜索已发现范围与在明确预算内扩展发现，返回未展开、不支持、错误、预算截断和缓存状态；空命中不表示全算例不存在。
- [x] 为 Agent 提供“概览 → 展开 → 描述 → 读取”和“搜索 → 确认上下文 → 读取”的完整使用示例，明确文档、Skill、训练知识和缓存的职责。
- [x] 验收 R7 及旧 MCP／CLI 的代表性兼容调用；直接更新受影响的 README、使用说明和项目设计，保留旧 Inspector 的摘要语义。

交付：在无需提前导出完整配置列表、无需输入精确 Java 标识符的条件下完成指定读取任务。默认不引入向量数据库；只有文本与别名检索出现有证据的不足时，再单独评估语义搜索。

## P4：后续受控写入迁移

本阶段已获授权，在只读阶段验收后按普通赋值规则族实施；结构操作及未知条件仍不自动开放。

- [ ] 按具体类型规则明确当前可写条件、新值验证、需保持属性和受影响对象，区别普通赋值与模型／方法切换等结构操作。
- [ ] 对规则完整的属性自动生成写入计划；显式禁止、特殊规则优先，未知条件不因存在 setter 而自动放行。
- [ ] 保留 `expected`、临近 setter 的必要重查、单次尝试、回读、Diff、显式保存与文件重载；复用确定拒绝和结果不确定的区分。
- [ ] 设计按目标及受影响对象范围进行修改验证的机制；在具有等价或更强依据前，保留现有快照要求，不为扩大覆盖直接移除检查。
- [ ] 在独立工作副本中验证正常修改、条件拒绝、过时状态、错误引用及持久化，按版本记录证据；逐批替代重复人工映射，不一次删除现有目录。

完成条件及行为边界见 Spec 的后续写入要求 W1—W4。发现 setter、编译成功和只读回读成功均不算写入验收。

## 代码职责与迁移方式

| 位置 | 计划变化 |
|---|---|
| `bridge/java/` | 新增运行时发现组件，向现有 `CatalogRuntime` 提供经过校验的计划；保留特殊类型与操作语义 |
| `core/` | 新增发现规范化、身份、规则选择、缓存和搜索编排；复用 `execution.py`，不允许请求直接注入 Java 调用 |
| `tools/catalog/` | 提供按需 API 声明及注解材料，支持自动计划校验；完整离线目录仍可用于维护与比较 |
| `catalogs/<release>/` | 保留现有映射；逐步分离生成缓存、类型规则、特殊约束和禁止规则，避免生成结果覆盖人工例外 |
| `core/service.py`、`interfaces/mcp_server.py`、`starbridge.py` | 增加统一发现接口，旧工具契约继续可用 |
| `bridge/runner/` | 复用会话身份、锁、超时、日志、保存与关闭机制；不因本阶段改写传输模型 |

新模块具体拆分在实施中依职责确定；本表不要求提前创建空模块。元数据可持久缓存，当前值和句柄有效性不能假设临时 Java 客户端退出后仍由 Java 内存保存。

## 验收与完成记录

Spec 的验收矩阵是本计划明确要求的验证范围，不额外扩展为全库测试重构。使用隔离工作副本，保存必要机器可读结果；不创建与行为无关或仅复述实现的测试。实现阶段按变更选择有意义的契约检查与真实 STAR 验收。

完成任务只在本计划更新勾选状态。产品能力与限制维护在对应使用说明，ADR 保留决策，Spec 维护契约，不在三个文档重复记录执行日志。P1—P3 的真实与模拟验收范围见[运行时发现说明](../runtime-discovery.md#验证范围)；共享 Plan/Spec 在 P4 完成后一起归档。
