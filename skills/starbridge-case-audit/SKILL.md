# STAR-CCM+ 算例审查

围绕用户的问题，给出能追溯到实际对象和值的审查结论。优先使用已有算例背景与有效会话；检查深度由任务决定，不把一次局部读取写成整份算例通过验收。

## 选择目标与取得证据

1. 从当前工具列表识别 StarBridge 服务及其发现／读取能力。宿主可能改写工具展示名称，按服务与工具说明对应方法，不拼接固定前缀。工具未连接时指出缺少 MCP 接入；仅安装本 Skill 不会安装或启动服务。
2. 对不熟悉的契约调用 `get_contract`，核对 `schema_version` 和本次所需方法。已有当前契约与有效定位可复用；缺少能力时报告具体缺口，不编造参数或自动改用任意 Java 宏。
3. 用户给出会话时先确认其状态；只给文件时，按用户指定或实际探测的安装打开隔离工作副本。未指定且不同算例或安装选择会改变审查结果时再澄清。选择与路径格式以工具契约为准，不固定 STAR release、端口或某台机器的目录。
4. 根据任务定位实际对象：已有路径从对应节点继续导航；已知类型和名称且目录接口支持时，先用 `find_objects` 定位，再描述和读取。需要运行时发现时，优先逐层浏览相关分支；只在无法缩小目标时使用有界扩展搜索，不能为了读取一个已知参数而默认遍历全树。先确认对象的父级、类型和物理角色，再描述并读取相关属性；同名对象不能只凭名称视为同一目标。只有明确的属性读取结果能作为当前值依据，描述中的默认值、可写标记和缓存搜索结果都不能替代它。

## 如何判断

优先核对用户给定目标与输入之间的关系，按实际任务选择下面相关项，不强制遍历全树：

- 参数：区分表达式、原始值与 SI 值，比较前确认单位和量纲。用户指定的参考值与算例当前值分别保留；单位等价不表示表达式依赖关系等价。
- 运动与时间设置：如果任务涉及转速、时间步长或周期，确认运动对象、时间离散方式和参考工况。只有确认是转／分钟的转速 `n` 时，才用 `T = 60 / abs(n)` 得到周期（s）；`n = 0` 不存在有限旋转周期。时间步长与每周期步数的关系只解释时间分辨率，不能据此认定收敛或精度满足要求。
- 模型与边界：核对设置属于哪个区域／边界、当前启用模型和当前 Profile 方法。不能因为显示某个数量就断言该方法生效，也不能把另一坐标系的向量分量直接比较。
- 相互引用：参数、场函数、报告或对象选择存在依赖时，沿已提供的关联查证。未读取到的依赖只列为待确认，不用命名习惯推断物理含义。

领域阈值优先使用用户给定规范或明确引用的工程依据。缺少依据时可以提出疑点与核验建议，但不自行设一个阈值并据此宣布算例不合格。缺少网格、求解记录或收敛证据时，不对网格质量、数值稳定性和 CFD 物理有效性作通过判断。

## 结果与会话处理

结论同时给出对象路径／名称、实际读取值及单位、比较依据，并区分已确认问题、待核实疑点与未覆盖内容。读取失败、分页未完成、搜索预算耗尽或不支持的属性应明确列出；空搜索结果不证明算例没有该设置。

本工作流不修改设置、保存算例或自动修复。若用户同时要求修复，先交付审查证据，再按当前工具契约和已授权的修改范围处理；本 Skill 不扩大操作权限。恢复连接或遇到 `uncertain` 时先查询状态和结果，不重发可能已执行的操作。

已有会话继续保留。为本任务新开的会话可在确认无需保留后正常关闭；若关闭因修改标志被拒绝，说明剩余会话状态，不用自动保存或 `discard` 掩盖它。报告实际使用的版本、审查范围和仍需用户提供的依据。
